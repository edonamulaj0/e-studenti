## Reporting a Vulnerability
To report a vulnerability for the `e-studenti` project, please consider the following general guidance for open-source projects on GitHub, as a specific reporting process is not outlined for this repository:

1.  **Check for existing security advisories or issues:** Before reporting, please check the repository's "Security" tab (if available) or existing issues to see if the vulnerability has already been reported or addressed.
2.  **Create a new issue (if no dedicated process):** If there isn't a clear "Security" tab or an email address for reporting, you can open a new issue on the GitHub repository. Please title it clearly (e.g., "Security Vulnerability: [Brief Description]") and include the following information:
    * A detailed description of the vulnerability.
    * Steps to reproduce the vulnerability.
    * The potential impact of the vulnerability.
    * Any suggested mitigations or fixes (if you have them).
    * Please mark the issue as **confidential** if GitHub's repository settings allow for it, to prevent public disclosure before a fix is available. If not, please exercise caution about including highly sensitive details in a public issue.
3.  **Expectation for updates:** The project maintainers will review the reported vulnerability. Response times may vary depending on the maintainers' availability and the severity of the issue. You can expect updates through the GitHub issue itself.
4.  **Vulnerability acceptance/declination:**
    * **Accepted:** If the vulnerability is accepted, the maintainers will work towards a fix and may engage with you for further details or testing. You may be credited for your discovery unless you prefer anonymity.
    * **Declined:** If the vulnerability is declined (e.g., it's not considered a vulnerability, already known, or out of scope), the maintainers will provide a reason for the decision.
